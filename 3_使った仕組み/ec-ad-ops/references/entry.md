# 工程0：入口（商品をハーネスに入れる）

通しの流れ（0 リサーチ → 0b 仕入れ先と商品チャンネル → 1 商品理解〈A〜K〉→ 2 お金 → 3 設計と依頼票 → 4 台本・映像・記事・店 → 5 運用 → 6 UI）は [flow.md](flow.md)。

商品がハーネスに入る道は2つ。どちらも最後は同じ `newec_harness/<商品名>/00_入口.md`（ひな形：`templates/product/00_入口.md`）を作り、工程1（[product-foundation.md](product-foundation.md)）に進む。

## A. リサーチエージェントに探させる（Seiyo「商品を探して」「プロダクトリサーチして」）
1. `ec-research` スキルを走らせる（Hookd で広告の多い Shopify を全部並べ、同じ商品の競合で実証し、80点以上の1商品だけを確定する）。80点未満なら確定しない（ec-research の決まり）
2. 確定したら、参入パック（商品の具体形・仕入れ先 URL・原価・参入コンセプト・ファネル・オファー骨子・競合サイト・参考広告）を `00_入口.md` に写す。写した所には「ec-research の参入パックから」と書き、レポートの URL を付ける
3. 仕入れ先に問い合わせる（[supplier.md](supplier.md)：Discord で「ありますか・いくらですか」を送り、返事の原価を 00_入口.md に書く。低ければ1回交渉）
4. Seiyo が「この商品で行く」と言ったら、**Discord に商品のチャンネルを作り**（supplier.md 1b。以後その商品の連絡はそこ）、工程1へ

## B. Seiyo が商品を渡す（「この商品でやる」＋URL・名前）
1. 受け取ったもの（商品ページ・仕入れ先・競合の URL、写真、メモ）をそのまま `00_入口.md` に置く
2. 足りない項目は、取れるものは取る（商品ページ・仕入れ先のページを読む。自社ストアにあれば Shopify の実物を読む）。取れないものは「Seiyo に確認」として一覧にし、1回でまとめて聞く
3. 仕入れ先の原価が無ければ、[supplier.md](supplier.md) で問い合わせる
4. 「この商品で行く」になったら、Discord に商品のチャンネルを作る（supplier.md 1b）
5. 工程1へ（足りない項目があっても、工程1は始めてよい。02 を作る前にそろえる）

## 00_入口.md で必ずそろえる項目（A・B 共通）
| 項目 | いつまでに | 使う所 |
|---|---|---|
| 商品名・何をする商品か（1行） | 工程1の前 | 工程1 全体 |
| 商品・仕入れ先の URL、仕様（素材・サイズ・使い方・**お手入れ〈洗い方・交換〉・同梱物**。分かる所まで。残りは工程1の A で商品ページの FAQ・説明書・競合ページから埋める） | 工程1の前 | 工程1 A |
| Discord の商品チャンネル（名前。1b で作った後） | 工程1の前 | 0b・5（注文・発送） |
| 分かっている競合（URL） | 工程1の前（無くてもよい） | 工程1 C の出発点 |
| 売値・セットの案、特典、定期便の有無 | 02 の前 | 02 |
| 原価（輸入の費用込み） | 02 の前 | 02 |
| Shopify のプランと支払い方法 | 02 の前（分からなければ一番高い率） | 02（15 の 1-1） |
| 1日の予算・月の上限・作れる新作の本数・仕入れの日数 | 03 の前（分からなければ空欄） | 03 |
| 広告を出したことがあるか（ある時は広告アカウント・キャンペーン） | 初日の設計の前 | 15 の 4B-10 |
