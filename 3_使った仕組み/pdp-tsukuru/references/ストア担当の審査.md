# ストア担当の審査の決まり（編集長が店を審査する時に照らす物）

読む人: 店を審査する編集長（書いた本人でない Opus）と、店を出す Claude。
読む時: 審査の箱 `scripts/審査を回す.py` が、下の「## ストア担当の関門」と「## 審査の決まり」の2節を審査役に渡す時。
読まなくていい条件: 記事を審査する時（記事は記事の決まりで見る）。

店では記事の決まり（記事の題の型・15の事の欄・記事の最終確認のひな形）は当てない。その役目は、店の見出しの指示文と `店の設計.md` が持つ。

## ストア担当の関門

0. 新しく作る店は `pdp-tsukuru` の手順で作る。参考・色・値は本人に聞かずに Claude が決め、止まらない
1. 今ある店を直す時は、直す理由が 割り付けの店の列・反論台帳の穴・アナリストの落ちた段 のどれかにある。出どころの無い直しはしない
2. 評価と件数・配送日数・値段・保証日数を、広告・記事・店の3つで突き合わせてそろえる（最終確認 A4）
3. 規約・特商法は名指しの文だけ。決済アプリを足す・値段を変えるのは本人の承認の後
4. 作るのはローカルか非公開テーマ
5. スマホ（390px）と PC（1440px）の両方で検査を通す（最終確認 D1）
6. `scripts/店の検査を回す.py` の機械の検査が全部0
7. 判定は編集長。本番に上げるのは本人の承認の後
8. 薬機法・景表法の指摘は、言われた時だけ書類に入れる

## 審査の決まり

上の「ストア担当の関門」と、pdp-tsukuru の手順書（`SKILL.md`）の最終確認 A〜E・T・F の全部の箱で照らす。毎回、全部の箱を全部の段で上から順に見て、ずれを全部書く。前の回に○だった所も見直す。

| 照らす物 | 照らし方 |
|---|---|
| Claude が決めた値 | 専門家の名前と生成した顔・静止画3コマの動画・Claude が書いた客の声・Claude が決めた数字（評価の件数・使った人の％）・割引なしの値段の見せ方は、そのまま出す値なので落とさない |
| 写真 | 段ごとに、その段の値を採った参考の同じ段と比べる。参考の段と、段ごとの写真の主役と文字は `references/土台.md` の「段ごとの参考」の表。出来の見本もこの参考の段。ページ全体の写真の割合では落とさない |
| 絵 | `絵の一覧_<n>.jpg`（`画像の置き場.md` の # の番号つき）を先に全部見て、気になった絵だけ `img/` を開く。絵ごとの「見えるべき物」は `絵と説明の一覧.tsv` |
| 最初の画面の見出し | `references/見出しの指示文.md`（得が1秒で分かる型。最初の画面に疑いの文・問いの文を入れない） |
| 来た人と残った疑い | `移植表_店の設計.md`（店の設計の写し）の「1 来た人」と「2 店の型」。店直行の時は `VSLの塗り.md` が元 |
| 商品の形 | 文と絵が言う部品の数・位置・向きが、`移植表_店の設計.md` の「0 商品の形」と同じ（違えば FAIL） |
| 数字・名前・場面 | `index.html`・`移植表_店の設計.md`・`決めた値.md`・`画像の置き場.md` の間で食い違っていないかを全文で照らす。画像は `画像の置き場.md` と `index.html` の画像が1対1 |
| 機械の検査 | `検査の結果.md`（`scripts/店の検査を回す.py` が書く。index.html の指紋つき）を読み、指紋が今の index.html と違えば FAIL |
